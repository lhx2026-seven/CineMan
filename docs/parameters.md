共有 15 組玩家可調來源規則。特殊廳動態建立時同樣套用。世紀、公會堂仍維持既定的票種與特別場停用規則。預算鎖定、獨家餐飲的有無不受此變更影響。

行政管理、玩家可調票價與餐飲售價皆使用 range 拉條，顯示即時金額，以 min 為新局預設值，step 從 min 起算，不提供文字輸入。優惠票維持唯讀公式。特殊廳動態建立、每場特別場展開時亦從 min 起始。合法存檔金額保留；舊版空值轉為 min，超界或不合步進的舊值由原生 range 對齊至合法範圍／步進。維護與雜支鎖定時同步停用拉條。海報與公仔數量維持數字輸入，依後續指定最少 1、預設 1、整數步進 1；舊存檔空值或無效數量讀取時修正為 1。依使用者後續指定，海報售價改為 0～1,000、公仔售價改為 0～10,000 的拉條，step 沿用原本的 1，新增於來源表以外的覆寫規則。目前「下一週」仍為預覽，沒有實際結算或財務公式。

## 待補充

- 學生軍警票、早場優惠票、愛心票由全票公式生成，改為唯讀。公式為學生軍警票＝全票−30、早場優惠票＝全票−60、愛心票＝全票×0.5。即時計算並保留精確金額，不額外取整；全票未填或不符限制時顯示「—」。不帶入或保存舊版手動輸入值，讀檔後依全票重算。世紀無此三票種，公會堂僅計算愛心票。
- 海報與公仔數量依後續指定最少 1、預設 1；售價已按後續指定改為海報 0～1,000、公仔 0～10,000。
- 使用者已確認 compute 負值代表從票房扣除，區間表達扣多／扣少，例如 -0.5 至 -0.65。原始端點保留，不當作 HTML 輸入上下限；未啟用抽樣或財報扣款。
- 使用者更正 bomb_film_distributor_guarantee 的 step 為 5,000；程式已更新，原始 Excel 的 0.05 僅保留作來源紀錄。
- gapWeeks 原樣保留，尚未套用扣款週期。

## 驗證

`CINEMAN_BASE_URL=http://127.0.0.1:8000 node tests/parameter-browser.cjs` 檢查五家戲院拉條上下限、min 預設、鍵盤步進、即時顯示、鎖定、優惠票重算、動態特殊廳／特別場、存檔還原與手機／電腦無溢出。進場效能測試確認新增規則腳本有正確預載，不新增資料庫請求。

行政管理各拉條靠近項目文字，與餐飲／週邊拉條均將 NT$ 和金額合併、水平置中。行政管理右上方即時計算五項預算的每週合計（含鎖定項目），尚不連動財務報表。特別場採依可用寬度自動換行的多欄排列，每場上方選片、下方票價；極窄螢幕（380px 以下）改同場左右排列。

行政管理五項採統一 96px 文字欄，項目名稱與金額同高，拉條保留於下排，雜支不因字短而改變起點。鎖定標籤位於名稱下方，不擠移拉條。

片商比例、bomb保底及世紀固定片租已接入distributor-rules.js，詳細時點及豁免規則見distributor-income.md。每片合約保存抽選結果；其餘未連動的compute參數仍保留，不推算未提供公式。

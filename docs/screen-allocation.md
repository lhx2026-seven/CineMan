# 電影院場地分派與測試

## 遊戲行為

玩家在首頁只能選戲院類型，不能控制影廳數、特殊廳或座位數。每次按「確定」進入新遊戲，首頁建立新的隨機 run；同一家戲院也會重新分派。不同抽樣仍可能偶然得到相同場地，不刻意排除重複結果。

新 run 的種子寫入 URL，遊戲使用同一資料版本及種子重建場地；重新整理與載入重試不會意外換場地。直接開啟沒有 run 的遊戲網址會自動建立 run。表單配置以 cinemaID + run 比對，只在同一局還原；新開局不沿用上一局的選片或價格。現行瀏覽器儲存仍以每家戲院一份草稿為上限，沒有無限制累積歷史局數。

外觀圖下方固定顯示總影廳數、總座位及特殊廳數／名稱；展開明細可查看每一廳的編號、類型及座位數。玩家介面沒有種子、指定廳數或重抽控制項。分派失敗會顯示重試；即使已選片，在場地分派成功之前也無法按下一週。

## 原始規則與優先序

來源是 `data/cinemas.json`，對應 CinemasList.xlsx、ScreensList.xlsx、LocationsList.xlsx。影廳分派使用前兩份；本次不任意產生地點，LocationsList 的空白仍代表不適用。

1. 總廳數只從該戲院明列的 screens 列等機率抽選；不是連續區間。YLC 不可產生 13 廳。
2. A/B/C/D/EXTRA 數量須符合各自 min/max，合計等於總廳數。EXTRA 包含在總廳數內。
3. 座位規格只取 ScreensList 的離散選項，不產生資料庫之外的席數。總席數滿足該列已填的最低值。
4. IMAX 300 席每家至多 1 廳；4DX 150 席至多 1 廳；VIP 20 席至多 2 廳。
5. 使用者已確認 `normal = 1 / screens`，不是高斯常態抽樣。既有 chance 欄的 null／空白為 0%，數值 0 與 1 保持 0% 與 100%。不存在的 chance 欄不是空白欄：B/C/EXTRA 的開放與否仍由 min/max 決定。
6. 硬條件優先。例如寶宮 3 廳的 A min=max=1，因此 A 必須出現；該列 A chance 的 normal 換算雖為 1/3，受限後出現機率為 100%。0% 明確禁止的規格不會作為補救抽出；無可行解直接報錯，不放寬限制。

## 機率公式（allocation-v1）

令 n 為本次總廳數，p(x,n) 為原欄位的機率換算：

- x=normal：p=1/n。
- x=null：p=0。
- x 為數值：p=x，必須介於 0 與 1。

### 類型數量

A chance 作為「這家戲院出現 A 廳」的機率。現行資料每列 A max 都不超過 1。先列舉滿足所有類型 min/max、總廳數、座位可行性與機率 0/1 限制的類型數量向量 c，再分為有 A 與無 A 兩組 F1、F0。

若兩組皆可行，P(A存在)=pA；選定組後，P(c|組)=1/該組向量數量。若只有一組可行，該組機率為 1。這避免「均勻抽所有數量向量」意外把 20% 的 A chance 改成取決於向量數量的比例。沒有獨立 chance 欄的 B/C/D/EXTRA 數量透過上述合法向量共同分配，不獨立抽數量後再截掉超額部分。

### 座位基礎權重

- A：500 席為 1−pNon500；800 席與 1000 席各為 pNon500/2。
- D：20 席為 pD20；50 席為 1−pD20。
- B：300、250、200 席各 1/3。
- C：150、100 席各 1/2。
- EXTRA：IMAX、4DX、VIP 各 1/3，後續再條件化每種上限。

給定類型數量，對逐廳座位序列 s 的基礎權重 W(s)=各廳基礎權重相乘。令 V 為符合總座位下限與特殊廳重複上限的序列集合：

`P(s | 類型數量、所有硬條件) = W(s) / Σ[t∈V] W(t)`，s 必須屬於 V。

實作以動態規劃計算剩餘合法序列的機率質量；每一步按「當前選項權重 × 剩餘合法質量」抽選。不使用無限制重抽、任意補廳或把座位補到下限。最後打亂影廳編號順序，仍保留相同配置。

這是有條件的機率模型：總座位下限與特殊廳上限可能改變原始座位權重的邊際比例。測試頁同時標出來源設定、A 受限目標及實測值。例如兩個 EXTRA 廳的有序抽樣有 9 種等權配對，剔除 IMAX+IMAX 與 4DX+4DX 後剩 7 種，VIP+VIP 的機率是 1/7，不是把所有無序組合視為等機率。

## 可重現性與版本

遊戲開局使用瀏覽器 crypto 產生 128-bit run 種子；抽樣使用固定的 FNV-1a seed hash + Mulberry32 PRNG。測試用途的種子可以輸入文字。此 PRNG 用於遊戲隨機與測試重現，不作密碼學用途。

結果包含引擎版本、資料指紋、cinemaID、seed、總廳數、類型數、逐廳資料、總座位及已換算機率。資料指紋涵蓋 cinemas/screens。相同版本、資料、seed、戲院與指定廳數可重現相同結果；資料更動或演算法升版後不保證重現。引擎快取以讀入後不變的資料物件為前提；測試更動資料請建立新的物件。

## 手動測試

開啟 `allocation-test.html`。此頁不讀寫玩家 localStorage，可：

1. 選戲院，讓總廳數隨機，或指定資料庫列出的廳數。
2. 輸入固定 seed 生成單筆；重按會得到相同結果；「換隨機種子」重新抽樣。
3. 批次抽樣 1–10,000 筆，可停止，顯示各廳數樣本量、平均總席、A 設定／受限目標／實測、D20 設定／實測、特殊廳與座位規格次數及違規數。
4. 下載 JSON，取得每筆種子、逐廳配置與驗證錯誤。批次第 i 筆種子為 `輸入seed/batch/i`（i 從 0 起）；將該值填回單筆種子，並保持戲院及廳數選項相同即可重現。

有限樣本有抽樣誤差，單次沒有出現某選項不代表機率為零。換不同 seed 重複批次可檢查穩定性。下載檔會保留單筆與批次各自的參數，兩者可以來自不同的測試設定。

## 自動驗證

無需安裝套件即可執行：

```
node tests/assignment-rules.cjs
node tests/assignment-generation.cjs
```

涵蓋全部 31 列規則的合法組合、106,500 次實際分派、五家戲院的廳數頻率、A/D20/non-500 機率範圍、固定 seed、空白與 0/100% 邊界、不可能配置，以及另 20,000 次有獨立解析答案的座位下限／特殊廳上限條件分布測試。頻率檢查採 6 個標準差加 3 筆容許值，固定種子避免隨機失敗。

可選瀏覽器驗證（需 Playwright 與 Chromium）：啟動靜態伺服器後執行 `CINEMAN_BASE_URL=http://127.0.0.1:8000 node tests/venue-browser.cjs`。已驗證 320／390／768／1440px 全五家戲院、逐廳加總、新選重抽、重整穩定、新局不還原舊選片、測試頁隔離及批次匯出、資料載入失敗與重試，且無水平溢出。瀏覽器測試輸出與下載暫存於 `/tmp`。

## 小城鎮限制（LOC08）

遊戲先抽地點，再將 locationID 傳入影廳分配。LOC08 先排除超過4廳的影廳數選項，再將 EXTRA min/max 一律覆寫為0；其餘一般廳範圍與最低座位數維持原資料約束。目前只有布洛威適用小城鎮，因此可抽3或4廳，兩種均有合法配置，沒有資料矛盾。模型按條件直接抽樣，不以反覆重抽來排除特殊廳。其他地點的抽樣分布不變。

配置保存locationID，驗證器使用相同地點限制。既有小城鎮存檔超過4廳時，以原種子從合法的3／4廳選項重建；若僅含特殊廳則依原廳數重建無特殊廳配置。座位總數可能隨之改變；地點、場地首抽其他結果、電影及已入帳票房不回算，既有固定租金也不重算。修正後保存配置，刷新不重抽；原先已無特殊廳的配置僅補上地點與限制資訊。

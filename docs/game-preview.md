# 第二頁：本週營運配置版型

沿用靜態伺服器即可，沒有新增套件或服務。首頁按「選擇」再按「確定」，經由布幕轉場進入 `game.html?cinema=C01`（C01–C05 對應五家戲院）。可使用此網址直接審閱各家版型；缺少或無效 cinema 會返回選擇頁，不預選戲院。首頁最新配色與使用者改成一致的「選擇」按鈕文案均保留。

## 已具備的版型與操作

介面採緊湊營運面板：外觀圖縮為識別縮圖、日期移至工具列，保留首頁品牌標題位置；預算及定價改為標籤／數值資料列，固定舊片與報表使用較薄的唯讀列，縮小片單、櫃台圖片、標題與內距。手機可操作欄位仍維持至少 44px 高。尚未提供正式唯讀欄位名單，因此不擅自鎖定目前可試填項目。

PC 與手機共用三個頁籤：預算配置、定價、選片。財務報表固定放在外觀照下方、頁籤上方；採收入／支出分欄、收入與費用明細、本週合計及損益的表格，非適用欄以「·」表示，待結算金額以「—」表示。一次只顯示一個設定頁籤面板，標籤列在捲動時固定於頂端；切換不重建表單，欄位、勾選與主打片占比保持。支援左右方向鍵、Home／End 與標準 tab／tabpanel 語意。上方外觀及下方櫃台與下一週為共用區。重新整理預設回預算配置，但已填內容會還原。

- 與首頁位置相同的 CineMan 品牌標題，以及所選戲院相同的外觀圖。
- 租金、硬體維護、人力、稅四項每週預算欄位，暫以 NT$ 金額呈現。
- 全票、優待票、早場票、爆米花、飲料的定價。
- 海報及公仔分別勾選才展開印量／製作量及售價；取消勾選會停用欄位，保留已輸入內容供再次啟用。
- 兩部本週新片占位，單選主打片後啟用場次占比（0–100%，每格 5%；初始顯示值 50% 僅為配置介面值）。三部固定舊片不提供調整控制項。
- 財務報表的收入、支出、損益與分項列，數字均為「—／待設定」，不計算或杜撰結果。
- 五張對應各戲院風格的售票櫃台 WebP，位於 `assets/cinemas/counters/`，寶宮採寬景構圖並保留水晶吊燈的展示高度；吊燈位於售票口正前方大廳中軸的天花板，左向右斜拍時僅下半部從畫面上緣入鏡，其餘按緊湊版面裁切。布洛威、YLC、公會堂採較明亮的中性白光，世紀維持原圖。
- 「下一週」在未設定本週主打片前為 disabled，顯示灰色不可按樣式與提示；只瀏覽選片頁籤或改其他設定不解鎖。設定任一主打片後才能開啟結算尚未開放的預覽對話框，不推進週數或產生營運結果。有效的已存選片配置可在重整後保持解鎖，各戲院分別判定。
- 各戲院獨立保存本機配置（`cineman.gameDraft.Cxx`），重整可還原；沒有後端／跨裝置同步。瀏覽器禁止儲存時可操作本頁，但明確提示不能保存。
- 布幕轉場支援減少動態效果；返回首頁依原規則保持無預選。

## 載入與轉場

卡片提供 640px WebP 衍生圖與 srcset；原始高解析圖保留作高密度備選。遊戲外觀縮圖沿用同一衍生圖，售票口另提供 960px 版本，依顯示寬度與裝置像素比選擇。十張 640px 圖合計 423,556 bytes，相較原圖 2,955,256 bytes 減少約 86%。

玩家手動選擇後才預載遊戲 CSS／JS、預取該戲院的遊戲文件；省流量模式不預載。不預載五家售票口。轉場關幕約 450ms、開幕約 450ms，外觀解碼最多等待 350ms，轉場期間暫停卡片漂浮動畫。保留減少動態效果設定及直接進入遊戲頁的支援。

Chromium 本機 390／1440px、2x 像素比測試：確定到布幕移除約 1.1 秒，卡片及外觀使用小圖、無資源載入錯誤，選片門檻正常；模擬圖片延遲失敗仍會解除布幕。此數字為本機測試，非 GitHub Pages 網路速度保證。

## 戲院識別與財報版面更新

CineMan LOGO 是返回首頁的連結，移除獨立返回按鈕。起始週次統一顯示 `2026 W1`。移除售票口上的選片提示與載入配置成功提示；保留本機配置還原、儲存狀態及儲存失敗提示，未選片仍停用下一週。

大於 760px 時，概覽以左右兩欄配置：左為放大的外觀圖及下方戲院名／小標，右為較窄的財報。手機改為全寬外觀圖（2:1）與介紹，再接財報；三個設定頁籤在概覽下方。外觀的 responsive sizes 同步更新以符合實際顯示尺寸。320、390、768、1440px 瀏覽器檢查通過：無水平溢出、左右／上下排列正確、週次一致、LOGO 導航正常、還原不再顯示成功提示，選片及還原後的下一週門檻正常。

## 週報與年報

財報內新增獨立的週報／年報頁籤，預設週報 `2026 W1`，年報 `2026`；切換時相應顯示本週／年度合計與損益。兩種報表的收入依序為電影票房、餐飲週邊、其它；支出依序為人事雜費、商品成本、硬體維護、行銷宣傳、公共事業帳單、租金、管理費（同一項）、稅。金額繼續待結算，不生成虛構數據。

財報頁籤支援左右鍵、Home／End、ARIA tab／tabpanel，與營運配置的三個頁籤各自獨立。320、390、768、1440px 驗證兩份報表項目、鍵盤切換、表單值保留、未選片仍禁止下一週，以及無水平溢出。

### 財報分類與損益呈現修訂

週報僅列電影票房、餐飲週邊收入及六項營運支出，不列其它或稅，底部統一呈現「營業利益」，移除原本週合計／本週損益的重複摘要。年報保留「其它」為收入，六項營運支出不含稅；先呈現「稅前淨利」，表外摘要另列「減：稅」，再呈現「年度損益」。稅不放在支出欄。仍未實作任何金額公式，所有金額待結算。四種螢幕寬度檢查通過項目分類、摘要順序、獨立頁籤操作、表單保留與未選片門檻。

## 隨機場地正式串接

外觀圖下方新增完整場地識別：影廳數、總座位、特殊廳數與名稱，以及可展開的逐廳類型／席數。分派使用 Excel 轉錄資料的硬條件、normal=1/screens、空白 chance=0%；公式與抽樣條件詳見 `docs/screen-allocation.md`。每次首頁確認會建立新 run 並重抽；同 run 重整維持相同配置，舊 run 的表單不套入新局。場地成功分派及完成選片兩個條件皆滿足才解鎖下一週。資料載入失敗提供重試，不生成補救用的假場地。

獨立 `allocation-test.html` 與玩家共用引擎，可做固定種子、指定廳數、批次統計與完整 JSON 匯出，不讀寫玩家存檔；主遊戲不顯示這些測試控制項。財務仍待公式，不因新增場地而擅自生成營運收入或成本。

### 場地資訊精簡

移除「電影院資料」可見標題，保留區塊無障礙名稱。摘要僅保留影廳數與總座位兩欄，搭配銀幕／座椅 SVG icon；特殊廳以「含 n 個特殊廳：名稱 × 數量」的小字呈現，沒有特殊廳則顯示「無特殊廳」。明細只保留「廳別／座位數」，一般廳顯示 `1廳`，特殊廳顯示如 `2廳（VIP廳）`，席數仍依真實分派結果，不套用示意數字。320／390／1440px 已檢查欄位、特殊廳標示與水平溢出；抽樣公式不變。

### 場地摘要橫向排列

摘要由左到右為影廳數、影廳明細按鈕、總座位數。明細按鈕不附括號廳數，以 aria-expanded／aria-controls 控制下方全寬表格，支援鍵盤 Enter／Space。特殊廳維持下一行小字，銀幕圖示改為弧形銀幕線條。320／390／1440px 已驗證排列順序、明細展開收合、鍵盤操作及無水平溢出；手機收合高度約 94px。

## 行政管理與銷售規劃調整

三個營運面板內移除與頁籤重複的標題，仍由 tab／tabpanel 的 aria-labelledby 保留名稱。

行政管理依序為人力預算（staffing）、餐飲成本（foodCost）、硬體維護（maintenance）、日常耗材（consumables）；移除原本的租金／稅預算輸入，不影響財報項目。四項初始均可調。硬體維護與日常耗材預留鎖定入口 `CinemaManagement.setBudgetLocks({maintenance:原因或true, consumables:原因或true})`；鎖定時停用欄位並標示鎖定，傳入空物件可解除。尚無鎖定規則，不擅自鎖定；僅保存數值，未將鎖定效果杜撰為玩家自行設定或跨週規則。

銷售規劃採電影票價三欄（全票／學生軍警票／早場優惠票）、特殊廳實際廳名票價、餐飲售價兩欄（爆米花／飲料 SVG icon）及海報／公仔兩欄。特殊廳依本局分派產生，沒有則隱藏整組；重複 VIP 廳共用一種 VIP 票價。特殊廳價格與一般設定一樣，在同一局重整後還原，不帶到新局。

已於 320／390／768／1440px 驗證新項目、鎖定／解鎖、三種特殊廳／無特殊廳／重複 VIP、票價及預算還原、商品開關展開與無水平溢出。可選測試：`CINEMAN_BASE_URL=http://127.0.0.1:8000 node tests/management-sales-browser.cjs`（需 Playwright、Chromium）。

# 本週大事：事件公告與決策版型

位置為第二個週次（workspace-bar）下方、營運頁籤上方。工作區週次 PC 20px、手機 18px；財報內週次維持原尺寸。移除「介面預覽」標籤。保留 GitHub 上使用者更新的「行政管理／銷售規劃／排片策略」頁籤。

目前沒有事件資料庫，第一週以空陣列初始化，整區自然隱藏，不顯示空白標題／框線／占位事件。未杜撰機率、事件效果、金錢扣除或週進程；「下一週」仍沿用原本預覽行為。

`weekly-events.js` 提供 `CinemaEvents.render({events, onDecision})`，供未來的每週開始流程呼叫。每次傳入當週抽出的事件清單，取代上一週公告；空清單會清空內容並隱藏整區。事件資料格式：

- `id`：唯一字串。
- `title`：標題字串。
- `message`：內容字串，可換行；以文字插入，沒有 HTML 解讀。
- `choices`：可省略或空陣列，此時僅公告並標示「無法干預」；有選項時，每個選項含唯一 `id` 與 `label`。

可決策事件需由實際遊戲層提供 async `onDecision({eventId, choiceId})`。等待期間停用該事件全部選項，成功後標示已決定且保持鎖定，失敗則重新開放重試。若未提供處理函式，選項保持停用，避免造成有實際效果的假象。事件條件、選項成本、結果公式、每週抽選、決策保存及與下一週的流程限制，待事件資料庫與遊戲規則建立時再接上；不擅自決定。

已以僅存在瀏覽器測試中的範例驗證 320／390／1440px：空事件隱藏、區塊位置、週次放大、公告與決策兩種呈現、成功鎖定、失敗重試、既有下一週門檻，以及無水平溢出。正式頁面沒有測試事件。測試指令（需 Playwright、Chromium 及本機靜態伺服器）：

```
CINEMAN_BASE_URL=http://127.0.0.1:8000 node tests/weekly-events-browser.cjs
```

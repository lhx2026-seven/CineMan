# 每週事件資料庫與執行規則

## 資料來源與更新

- `data/source/Event.xlsx`：保留作者可編輯的文案、條件描述、中籤權重、可重複與選項。已套用對話確認的誤植修正。
- `data/event-rules.json`：每個eventID對應可驗證的條件與效果，不執行Excel文字或公式。
- `python3 scripts/import-events.py [另一份Event.xlsx]`：驗證ID、權重與選項後，產生`data/events.json`、`data/events.js`。
- `python3 scripts/import-events.py --check`：檢查產物是否同步。使用openpyxl讀取Excel。
- 修改後執行`node scripts/build-game-runtime.cjs`，一起更新網站bundle、HTML及首頁預載；不在玩家進場時讀取Excel或發送額外資料庫請求。

probability填0到1之間的正數（例如33%填0.33，也可使用Excel的33%格式），不填數字33。

新增事件時保留原十欄，在Excel新增一列及未用過的eventID，並在event-rules.json新增同ID規則。既有條件／效果可直接組合；新的遊戲能力需要擴充event-rules.js並測試。可加`enabled`（Y/N，預設Y）、`cooldown_weeks`、`max_per_year`（非負整數）欄位。暫停事件請設enabled=N，不刪除曾經使用的ID；舊存檔仍須辨識舊事件。不要把舊ID改作另一件事。玩家已抽中的文案、選項、效果及金額凍結在存檔，不因後續修改資料庫而重抽或回算。

## 抽選與時點

2022 W1為無事件開局，不抽選、不顯示本週大事；從2022 W2起開始。後續年份的W1仍正常抽選。尚停在2022 W1的舊存檔會清除該週已抽事件及其未結算效果，恢復事件前預算；已前進的存檔不回算歷史。

每個營運週至多一件事件，在繳費通知之後顯示。從符合條件且未停用的事件，按probability相對權重抽一件；不作獨立的百分比擲骰。兩件100%各50%；100%、100%、50%為40%、40%、20%。repeatable=N代表每局最多抽到一次，拒絕選項也算已抽過。效果仍在作用期時，整筆事件不得重抽。100週限制為從上次抽中日起的滾動冷卻，不是固定偶數年份。

條件中的預算、成本、人次、開賣與特別場、上映片單均讀取上一個營運週；年份／週次窗口、土地權屬與影廳設備依當前場地及遊戲時間。一般預算條件不會因當週玩家改拉條而重抽。上一週資料尚不存在（例如開局W1）時，僅資料足夠的條件可參選。老存檔導入時不虛構過往八週的預算／損益，四週／八週連續條件需累積足夠的實際紀錄。過去年度若已有完整50週票房與營運支出帳本，首次載入可依現行年報公式還原年度損益供條件使用；資料不完整則不虛構。

依賴事件的未解決狀態，例如逃生通道未清理、消防待複查、勞資問題，保存在facts。每週重新檢查；未抽中不保留名額，條件仍存在則仍可參選，處理完成清除旗標。沒有把未抽中的事件排成強制補發佇列。

《銀幕不熄》第四週原有固定連署劇情占該週事件名額，不再額外抽第二件隨機事件。虛擬年度會議不抽事件。無候選事件則不顯示空白彈窗；本版有可重複的anytime事件維持一般週的候選池。

抽選使用獨立的events/v1種子流（局種子／週次），不影響影廳、電影、餐飲等既有亂數。每週結果、已決策與已讀狀態都保存；刷新不重抽、不重複扣款，未完成選項／確認前不能前進下一週。

## 效果及結算

- 未註明期限只作用本週；連四週包含本週；接下來一週從下週起。
- 鎖定為：當週強制設定拉條並灰鎖，可超出平常拉條上限；到期恢復事件前的值與範圍，不把事件鎖變成永久鎖。
- 強制加：獨立加到對應財報支出，不更改玩家預算拉條。不再乘人事1.2。
- 上座率效果只作用普通tier電影的一般場；special片、額外特別場不套用。普通片最終不超過100%；明訂歸0優先於0.1%最低上座率。
- 特別場200人基準為明確特別場效果，覆蓋原地點基準，但仍用原特別場票價／原始上座率公式。
- 停業與明訂票房歸0是收入限制，包含special影片；停業也包含特別場、餐飲周邊與當週產生的空間收入，不取消之前已產生、本週才入帳的收據。
- 餐飲年度累積成本為0的規則優先於所有事件餐飲加成；海報、公仔仍分別結算。
- 營運效果依該營運週結算，延續既有下一週入帳及W50虛擬會議歸當年制度。事件現金收入列其它收入；事件人事／商品／硬體／行銷／其它支出直接進對應列。既有已入帳收據不回算。
- 每週保留最多八筆前週判斷資料；抽選／效果／入帳稽核保留整局，年度損益在年會凍結後用於來年條件。

# IndexedDB 自動存檔與繼續經營

## 玩家操作

首頁提示列由左至右為自動存檔 ON／OFF、請選擇你想經營的電影院、繼續經營。開關預設 ON；右側紀錄顯示為「寶宮戲院 2026年1週」，沒有紀錄則顯示尚無存檔、停用繼續經營。

本版保留一筆最近一局的自動存檔。ON 時新開局分派成功及設定變更會更新紀錄；OFF 停止寫入，保留原紀錄，仍可繼續經營。重新選戲院確認建立新 run，仍會重抽場地；繼續經營與同 run 重新整理則還原原有場地，不抽新場地。OFF 開新局不覆蓋先前紀錄。

存檔限同一裝置、同一瀏覽器及相同網站來源，不是帳號／雲端同步。清除網站資料會清除本機存檔。此功能不提供離線網頁快取，也不實作目前尚未定義的週進程、事件效果或財務結算。

## 儲存內容與格式

`autosave.js` 對外提供 `CinemaSave.getSettings / setEnabled / getLatest / save / subscribe`。資料庫 `CineMan`，版本 1：

- preferences：key 為 autoSave，保存 enabled。
- saves：key 為 latest，保存最近完整 checkpoint。

checkpoint 含存檔版本、cinemaID／cinemaName、runId、遊戲年／週、savedAt、完整場地 allocation、表單 values、兩項預算鎖定狀態、營運頁籤、財報頁籤及影廳明細展開狀態。表單包含行政管理、一般／特殊廳票價、餐飲／商品設定、主打片及整數場次、特別場選片與價格。

讀回時檢查版本與必要欄位。場地使用已存快照，並依目前資料庫規則驗證，不依新 seed 重新生成。規則不相容、存檔損壞或讀取失敗時，繼續經營顯示錯誤及重試入口；不藉由重抽來偽裝讀檔成功。新局的場地資料成功取得後才建立新 checkpoint。

## 自動保存時機與一致性

表單 input／change、頁籤切換、影廳明細切換、預算鎖定變動會保存；進入有效的新局也保存初始場地。pref 與 checkpoint 在同一個 readwrite transaction 內讀取／寫入，每次重新檢查是否 ON，避免另一分頁切 OFF 後，舊遊戲分頁仍依快取設定寫入。

「已自動存檔」只在 transaction 完成後顯示；處理中及寫入失敗各有獨立狀態，不樂觀宣稱成功。點 LOGO 返回首頁與按下一週預覽會等待當前保存工作完成。頁面隱藏／離開亦嘗試保存，但強制關閉或刷新時尚未完成的非同步 transaction 不保證完成；應以已自動存檔狀態為準。失敗時 IndexedDB 原子性保留上一筆完整 checkpoint，不會把半筆狀態當成可繼續紀錄。

以 BroadcastChannel 通知首頁紀錄與偏好變動，不支援時首頁重新取得焦點也會更新。DB 被禁止或不可用時，首頁停用繼續經營並說明原因；新遊戲仍可操作但不假裝存檔成功。開關 OFF 仍會保存開關偏好本身，不寫遊戲 checkpoint。

舊版 localStorage 草稿只作相同 run 的一次相容讀取（ON 時），之後所有遊戲設定寫入均使用 IndexedDB。舊的首頁選擇暫存鍵仍為選擇頁本身使用，不是自動存檔來源。

## 驗證

`CINEMAN_BASE_URL=http://127.0.0.1:8000 node tests/autosave-browser.cjs`（需本機靜態伺服器、Playwright、Chromium）。

已驗證 ON 保存完整配置與繼續、原場地不重抽、OFF 偏好重整保留、OFF 不覆寫、重新選戲院新 run／新配置、跨分頁 OFF 禁止寫入、320／390／1440px 首頁位置及無水平溢出，以及 IndexedDB 被禁止時的新局可操作／讀檔失敗不重抽。

另外以持久化 browser profile 實測完整關閉瀏覽器再開啟仍可讀回配置、頁籤與鎖定狀態；模擬存檔 put 寫入失敗，確認顯示失敗、沒有未處理錯誤且上一筆完整紀錄不變。既有場地與排片測試已配合非同步存檔，等 transaction 完成後才進行還原驗證。

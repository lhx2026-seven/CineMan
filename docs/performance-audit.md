# 程式清理與效能檢查

本次不改遊戲規則、財報金額、存檔格式或既有視覺。

## 已清理／修正

- game.css移除40條已無HTML/JS使用的舊版佔位海報、mini-poster、舊財報摘要等樣式，含響應式舊覆寫。沒有移除仍有效的階層樣式。
- game.js移除只寫不讀的saved變數；週次按鈕文字只在標籤改變時替換，避免每次控制項更新都重建子節點。
- home-save.js合併尚在進行中的首頁存檔刷新，初次pageshow不重複初始化；bfcache恢復、視窗focus及存檔通知仍會刷新。存檔通知在讀取途中到達時，會在讀完後補讀，避免漏掉新寫入。
- 首頁偏好設定與存檔清單並行讀取。autosave.getByRun正常以runId查找時只讀該筆；只有找不到時才讀legacy/latest相容紀錄。
- box-office.advance不再深拷貝整份歷史票房收據；保留既有唯讀收據，另建收據陣列、年度合計與單片累積物件。也移除一份立刻重複的電影狀態深拷貝。輸入狀態不受修改。
- build-game-runtime同時依內容產生首頁autosave.js、home-save.js、data/cinemas.js的版本碼，避免手動版本字串漏更新造成舊腳本快取。

## 量測

本地Chromium／同一執行環境測試，非實機網路速度保證：

| 項目 | 修改前 | 修改後 |
|---|---:|---:|
| 首頁初次存檔清單讀取次數 | 2 | 1 |
| 25次連續focus事件的清單讀取次數 | 25 | 1 |
| 三局各240週、後期190～240週的純票房進週中位數 | 7.61 ms | 5.05 ms |
| 同組進週p95 | 11.10 ms | 11.42 ms |

長局樣本最後一份票房ledger約333KB，原本每次深拷貝約2.4ms。三局累計票房校驗值修改前後完全一致（352415073）。中位數改善，p95並未證明改善，不能推論所有裝置的每次進週都加速。80次連續滑桿輸入仍合併為一次存檔，處理約6ms。

## 保留的必要資料與限制

- game-runtime.js是目前前台使用的產物；來源模組、data JSON/JS及匯入Excel各有建置／測試用途，不是多餘腳本。進場測試確認只載入一份遊戲runtime，沒有另外要求cinemas JSON。
- assets目前都可對應至首頁、遊戲、響應式圖、海報或年度會議，沒有因此刪圖。
- 首頁存檔列表仍讀取完整存檔；大量長局存檔會增加IndexedDB傳輸／記憶體負擔。此次減少重複讀取，未改DB schema；若將來需處理大量存檔，可再拆獨立摘要索引。
- 完整票房歷史驗證與存檔仍隨遊戲週數增長；未為了速度跳過驗證。電影抽選仍會查系列／歷史。大型狀態的首次載入及低階裝置需另行實機量測。
- 現有卡片漂浮、陰影、亮度與背景模糊均保留；它們可能產生GPU繪製成本，但本次沒有證據認定它們是卡頓主因。

回歸涵蓋：首頁讀檔合併、進場／錯誤復原、滑桿及LOGO立即離頁保存、周邊庫存、年度會議與跨年、世紀票房可見性、票房金額及不修改原輸入的測試。
